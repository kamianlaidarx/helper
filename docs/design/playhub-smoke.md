# playhub 真机冒烟测试单（P2）

> 适用版本：`d3ac847` 及以后。执行环境：**云电脑**（`C:\helper-main`）。
> 本机（开发机）禁止启动机器人：那里绑着你的真实微信号，一启动就会往真实群推送。
>
> 目标不是"功能全过"，而是**证伪三件事**：①关键词在真实群里的误触率；②回包在手机端看起来是否可用（行宽、emoji、@ 位置）；③框架侧能力（群角色、成员快照、入群事件）与我的假设是否一致。

### 天气配置（可选，但这是本轮唯一的新外部依赖）

`bot_config.json → plugins` 下加：

```json
"playhub": {
  "enabled": true,
  "weather_provider": "qweather",
  "weather_api_key": "<控制台里的 Key>",
  "weather_api_host": "<控制台里的 API Host>",
  "weather_timeout_seconds": 3
}
```

**`weather_api_host` 必须填**：和风 2023 年起给每个账号一个专属域名（形如 `abc1234xyz.re.qweatherapi.com`），旧公共域名 `devapi.qweather.com` 用新 key 会返回 403/404（2026-11-06 实测过）。填了 `weather_api_host` 就不必再填 `weather_geo_host`——城市搜索与预报共用这一个域名。

不填 key 也是合法状态：`天气 成都` 回一张卡，内容是「天气服务暂时连不上 / 过一会儿再发一次试试」，**不会编数据**，也**不会把配置项贴进群聊**（配置方式只写在本文档与日志里）。

配了 key 时，`天气 成都` 的行为是**异步**的：机器人先不回话，1–3 秒后直接发一张天气卡（不会先回一句「正在查」）。这是设计选择——宁可安静几秒，也不刷两条消息。若那一刻后台队列已满（群里同时大量慢活），会退化成同步查询，最多多等 3–6 秒。

## 三、5 个高危开关怎么开（本版**没有**群内开启命令）

`结婚/闺蜜/结拜/雇佣/纳妾/宝宝` 默认关。开法只有一条：直接写库。

```sql
-- 存档路径：.runtime\playhub\<sha256(账号)[:16]>\playhub.sqlite3
INSERT INTO kv(room, key, value, updated_at)
VALUES ('<群id>@chatroom', 'feature.marriage', '1', strftime('%s','now'))
ON CONFLICT(room, key) DO UPDATE SET value='1', updated_at=excluded.updated_at;
```

把 `feature.marriage` 换成 `feature.kinship` / `feature.employ` / `feature.concubine` / `feature.baby`。
`<群id>` 就是 `群名@chatroom` 那种 id，在 `logs/bot.log` 里能搜到。

**验开关生效**：关着时发 `结婚`、`结婚 @某人` 都**完全没反应**（开关判定在回卡之前）。
开着时裸发 `结婚` 回玩法卡，`结婚 @某人` 才发邀请。所以「发结婚没回复」= 开关关着，
不是 bug，见下一条命令。

## 四、最该盯的四个真实风险

1. **误触**：在群里正常聊 50 句（含"今天天气不错""签到率""宝宝巴士""结婚照"），统计被误触几次。
   - 预期：`宝宝巴士`/`结婚照` 不会触发（整条消息必须等于关键词）；`今天天气不错` 不触发（`天气` 必须带城市）。
   - **只要出现一次误触，就把原句记给我**——这是唯一需要改词的信号。
2. **连发**：同一秒连发 5 条 `签到`（或 5 条 `猜成语`），看队列（128）下有无丢包、有无重复发币。
3. **群角色**：用**非好友**的普通成员号发 `改名 现在`，确认是"拒绝"而不是"没反应"（两种都算通过，但要记下是哪种——我在本机拿不到真实角色值）。
4. **入群事件**：拉一个人进群，然后 `邀请`。三种结果都要记：
   - 有归属 → `👤 1. <邀请人> — 1 人`（最好）
   - 只有群级 → `🚪 入群 1 次 · 邀请入群 0 次`
   - 完全没有 → `📨 近 7 天没有入群记录`（说明该版本微信的入群消息文本/assets 变了，我需要看日志）

## 五、回传什么

| 文件 | 用途 |
|---|---|
| `logs\bot.log` | 插件加载、异常栈、群 id、框架事件原文（**最重要**） |
| `.runtime\playhub\<hash>\playhub.sqlite3` | 我能在本机复算榜单/钱包/邀请是否一致 |

回传前可自查一致性（可选）：

```sql
-- 每个玩家的流水合计应等于余额（不符就是发币 bug）
SELECT w.room, w.uid, w.currency, w.balance,
       (SELECT COALESCE(SUM(delta),0) FROM wallet_ledger l
         WHERE l.room=w.room AND l.uid=w.uid AND l.currency=w.currency) AS ledger_sum
FROM wallet w
WHERE w.balance <> (SELECT COALESCE(SUM(delta),0) FROM wallet_ledger l
                     WHERE l.room=w.room AND l.uid=w.uid AND l.currency=w.currency);
```
返回空 = 账平。

## 六、故障对照表

| 现象 | 先查 | 多半是 |
|---|---|---|
| 群里发什么都没回 | `logs/bot.log` 有无 `playhub 取不到登录账号` | 成员目录没就绪（`ctx.members.account` 为空） |
| 只有部分词有回 | 该词是否在 5 个开关里 | 开关默认关，见第三节 |
| `no such table: kv` | 存档路径是否可写 | 目录权限 / 半截拷贝的库 |
| `天气 成都` 立刻回"没配置" | `bot_config.json` 那一节是否在 `plugins` 下 | 层级写错，或 key 为空 |
| 天气返回"暂时不可用" | 日志里的状态码 | 缺 `weather_api_host`（403/404）；连续 3 次失败会熔断 5 分钟 |
| 天气「永远不可用」但 key 看着没问题 | 机器上是否设了 `ALL_PROXY` / `HTTP_PROXY` | `urllib` 会走系统代理；指向一个不可用代理时天气必然失败（开发机实测就是这样）。清掉代理再试 |
| `天气 成都` 查完一次，紧接着再问**又等 1–3 秒** | —— | 已知设计代价：缓存由后台线程排队、在**下一条消息开头**才落库（worker 不碰数据库）。多花一次额度，不影响正确性 |
| 回包发不出去 | 日志 `playhub 回包发送失败` | 账号被限制/网络；插件本身不会崩 |
| 电脑重启后排行榜清零 | —— | 不会：数据在 SQLite；只有**进行中的对局**（猜题/接龙/切磋）在内存里，重启即丢 |
